STEP 1

Create the VPC

VPC Dashboard → Your VPCs → Create VPC

Name tagProduction-VPC
IPv4 CIDR block10.0.0.0/16
IPv6No
TenancyDefault
CLI
aws ec2 create-vpc \
  --cidr-block 10.0.0.0/16 \
  --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=Production-VPC}]'
💡Explain: /16 gives 65,536 IPs. A Main Route Table is auto-created with the VPC.
STEP 2

Create & Attach Internet Gateway

VPC Dashboard → Internet Gateways → Create Internet Gateway

Name tagProduction-IGW

After creating → Actions → Attach to VPC → Select Production-VPC

CLI
# Create
aws ec2 create-internet-gateway \
  --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=Production-IGW}]'

# Attach to VPC
aws ec2 attach-internet-gateway \
  --internet-gateway-id igw-xxxxx --vpc-id vpc-xxxxx
💡Explain: One IGW per VPC. Without it, nothing can reach the internet.

Create 4 Subnets (2 Public + 2 Private)

CLI (example for 2 subnets)
# Public Subnet A
aws ec2 create-subnet --vpc-id vpc-xxxxx --cidr-block 10.0.1.0/24 \
  --availability-zone ap-south-1a \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=Public-Subnet-A}]'

# Private Subnet A
aws ec2 create-subnet --vpc-id vpc-xxxxx --cidr-block 10.0.2.0/24 \
  --availability-zone ap-south-1a \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=Private-Subnet-A}]'
💡Explain: /24 = 256 IPs, AWS reserves 5, so 251 usable. Always use 2+ AZs for HA.
STEP 4

Allocate Elastic IPs for NAT Gateways

EC2 Dashboard → Elastic IPs → Allocate Elastic IP address (×2)

  • Name: NAT-GW-A-EIP
  • Name: NAT-GW-B-EIP
CLI
aws ec2 allocate-address --domain vpc \
  --tag-specifications 'ResourceType=elastic-ip,Tags=[{Key=Name,Value=NAT-GW-A-EIP}]'

aws ec2 allocate-address --domain vpc \
  --tag-specifications 'ResourceType=elastic-ip,Tags=[{Key=Name,Value=NAT-GW-B-EIP}]'
⚠️Unused EIPs cost ~$3.65/month. Release them after the demo.

STEP 7

Associate Subnets with Route Tables

Select Route Table → Subnet Associations → Edit

Public-RTBPublic-Subnet-A + Public-Subnet-B
Private-RTB-APrivate-Subnet-A
Private-RTB-BPrivate-Subnet-B
💡Unassociated subnets use the Main Route Table (no IGW = private by default).
STEP 8

Enable Auto-Assign Public IP

VPC → Subnets → Select public subnet → Actions → Edit subnet settings

  • ✅ Enable auto-assign public IPv4 on Public-Subnet-A
  • ✅ Enable auto-assign public IPv4 on Public-Subnet-B
💡Without this, EC2 in public subnets won't get public IPs and can't be reached from internet.

🔧 Troubleshooting

Public instance can't reach internet
  • Instance has a public IP?
  • Security Group allows outbound?
  • Route Table has 0.0.0.0/0 → IGW?
  • IGW is attached to the VPC?
  • Subnet is associated with the correct Route Table?
Private instance can't reach internet
  • Route Table has 0.0.0.0/0 → NAT Gateway?
  • NAT Gateway status is Available?
  • NAT Gateway has an Elastic IP?
  • NAT Gateway is in a public subnet?
  • NAT's public subnet has route to IGW?
Can't SSH from public to private instance
  • Private-SG allows SSH (22) from Web-SG?
  • Both instances in same VPC?
  • Using correct private IP (10.0.x.x)?
  • Key pair available on the public instance?
